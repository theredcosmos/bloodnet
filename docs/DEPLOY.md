# Deploying BloodNet for free (Render + Aiven MySQL)

The result is a public URL that anyone, a recruiter for example, can open:

```
browser ──► bloodnet-web (Render static site, Angular)
               │  /api/*  rewritten (same origin, no CORS)
               ▼
            bloodnet-api (Render web service, Spring Boot in Docker)
               │  JDBC over TLS
               ▼
            Aiven MySQL 8 (free plan)
```

Everything here is free. The trade-off is that the free API **sleeps after 15 minutes without traffic**,
so the first request after that takes about 1 minute while it wakes up. The static site never sleeps.
Before a demo, open the site a minute early.

## 1. Database: Aiven free MySQL

1. Sign up at aiven.io and create a service: **MySQL**, plan **Free**, any region near you.
2. Wait until it shows *Running*. Then copy the **Host**, **Port**, **User** (`avnadmin`) and **Password** from *Connection information*.
3. Your JDBC URL is:
   ```
   jdbc:mysql://<host>:<port>/defaultdb?sslMode=REQUIRED&connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true&rewriteBatchedStatements=true
   ```

The app creates the tables itself through Flyway on first start. Every table has a primary key, which Aiven requires.

## 2. Push the code to GitHub

Render builds from the GitHub repo (`theredcosmos/bloodnet`), so the branch you deploy must be pushed.
`render.yaml` deploys the repository's default branch unless you change it in the Render dashboard.

## 3. Render: create both services from the blueprint

1. Sign up at render.com with GitHub and allow it to read the `bloodnet` repo.
2. Go to **New → Blueprint**, pick the repo, and Render reads `render.yaml`.
3. Render asks for the values marked `sync: false`:

   | Key | Value |
   |-----|-------|
   | `DB_URL` | the JDBC URL from step 1 |
   | `DB_USER` | `avnadmin` |
   | `DB_PASSWORD` | the Aiven password |
   | `CORS_ORIGINS` | `https://bloodnet-web.onrender.com` (your static site URL) |
   | `SEED_PASSWORD` | a password of your choice for the demo accounts |

   `JWT_SECRET` is generated by Render. Never commit it.
4. Click **Apply**. The API build takes about 5 to 8 minutes, the first time mainly because of Maven dependencies.

**If Render gives the API a different hostname** than `bloodnet-api.onrender.com`, which happens when
the name is taken, edit the three `destination:` lines in `render.yaml`, push, and let it redeploy.

## 4. Check it works

- `https://bloodnet-api.onrender.com/actuator/health` returns `{"status":"UP"}`.
- `https://bloodnet-web.onrender.com/find` shows the public "find blood" page.
- Sign in at `/login` with `admin@bloodnet.local` and your `SEED_PASSWORD`.
- `https://bloodnet-web.onrender.com/swagger-ui.html` shows the API docs.

## 5. Optional: fill it with realistic demo data

The seeder goes through the real API, so every business rule is applied. Run it from your machine:

```bash
mysql --ssl-mode=REQUIRED -h <host> -P <port> -u avnadmin -p defaultdb < scripts/demo_reference_data.sql
```

```bash
python scripts/seed_demo_data.py --base-url https://bloodnet-web.onrender.com --skip-sql
```

The script reads `SEED_PASSWORD` (and `ADMIN_EMAIL`/`ADMIN_PASSWORD` if set) from your local `.env`.

## Notes and limits

- **Demo accounts are public.** Anyone who knows the demo password can sign in as admin. That is fine
  for a portfolio demo. For anything real, set `SEED_DEMO_USERS=false` and use `ADMIN_EMAIL`/`ADMIN_PASSWORD`
  or `ADMIN_SIGNUP_CODE` instead.
- **Rate limits** are counted per client IP from `X-Forwarded-For` on Render. A client can fake that
  header, so on this host the limits only slow down casual abuse. The Docker Compose setup is not
  affected: nginx sets `X-Real-IP` and the app port is not exposed.
- **Memory:** the free instance has 512 MB, so `JAVA_OPTS` caps the heap at 60% and uses the serial GC.
  If the logs show `OOMKilled`, lower `MaxRAMPercentage` to 50.
- **Scheduled jobs** (expiry, rebalancing, stock summary) only run while the API is awake.
  The dashboard's "stock refreshed" time shows when the summary was last rebuilt.
- **Running locally instead:** `docker compose up -d --build` (see the comments at the top of `docker-compose.yml`).
