# Decisions log

One line per choice and the reason. Newest problems found while building are at the bottom.

## Architecture
- **Modular monolith, not microservices**: one deployable and one DB transaction for allocation; the module boundaries keep the option to split later.
- **Spring Modulith**: module boundaries are checked by `ModularityTest`, which fails the build on a cross-module import of `internal` classes or a dependency cycle.
- **Public API = top package of a module, everything else in `internal`**: the Modulith default; no extra annotations needed.
- **`shared` module** for enums, `AuthUser`, exceptions, audit and the error handler: everyone needs them and they have no dependencies of their own.
- **Banks live in `inventory`, hospitals in `request`**: no separate "directory" module just for two lookup tables.
- **Transfer → inventory communication by events**: inventory already depends on transfer (for the event types); a direct call back would create a cycle.
- **Synchronous `@EventListener` for stock movement**: stock and transfer status must commit or roll back together.
- **`@ApplicationModuleListener` (async, after commit) for notifications**: a notification failure must not undo a business action.
- **Modulith JDBC event registry**: async events are stored in the publisher's transaction and resubmitted after a crash (outbox-style).

## Data
- **MySQL 8 + InnoDB**: row locks, `SKIP LOCKED` and `ST_Distance_Sphere` are all built in.
- **Flyway owns the schema, Hibernate `ddl-auto=validate`**: schema changes are reviewed SQL files, and a mismatch fails at startup.
- **Enums stored as strings**: readable in SQL and safe when enum order changes.
- **All times UTC (`Instant`, `DATETIME(6)`)**: no daylight-saving or server-zone surprises.
- **Compatibility matrix as a table, generated by SQL rules in V2**: auditable, and no 126 hand-typed rows.
- **Plasma/platelets use the reverse-ABO rule and ignore Rh**: simplification for the project; documented here.
- **Banks store lat/lng as DOUBLE, distance via `ST_Distance_Sphere(POINT(lng, lat), ...)`**: simple; a SPATIAL index would be the next step at scale.
- **`stock_summary` table refreshed every minute**: the dashboard polls a tiny table instead of re-aggregating `blood_unit` for every browser.
- **`request_allocation` history table**: lets us prove "one active allocation per unit" in tests and audit who got what.

## Concurrency
- **Request row lock (`PESSIMISTIC_WRITE`)**: two staff clicking Allocate on the same request run one after the other.
- **Units picked with `FOR UPDATE SKIP LOCKED`**: parallel allocations for different requests take different units without waiting.
- **`READ_COMMITTED` for allocation**: avoids REPEATABLE_READ gap locks that block inserts and cause deadlocks; we lock every row we change anyway.
- **FEFO (first-expired, first-out) after exact group**: less wastage.
- **`@Version` on entities**: optimistic locking for single-row edits like discarding a unit.
- **`Propagation.MANDATORY` on inventory's allocator**: calling it outside the request transaction is a bug, so it throws.
- **Audit aspect wraps outside `@Transactional`**: failures still get audited, and no thread holds two pool connections.

## Security
- **Stateless JWT (HS256), 8h expiry**: no session store; the token carries role and bank/hospital id.
- **BCrypt for passwords**: slow and salted.
- **CSRF disabled**: the token is in the `Authorization` header, not a cookie.
- **`@PreAuthorize` on endpoints + `BankAccess` checks in services**: role checks are declarative; "own bank only" needs the loaded entity, so it is also checked in code.
- **Login takes the same time for unknown emails**: a dummy BCrypt check prevents user enumeration by timing.
- **Token kept in `sessionStorage` on the frontend**: simple, cleared when the tab closes. An httpOnly cookie would resist XSS better but needs CSRF protection back.
- **Demo users created by the app, password from config**: hashes can't be pre-computed in SQL, and no secret is in source.
- **First admin from `ADMIN_EMAIL`/`ADMIN_PASSWORD` at startup**: a fresh install always has someone who can log in and add users; it does nothing once the account exists.
- **Admin sign-up page gated by `ADMIN_SIGNUP_CODE`**: an open "sign up as admin" form would let anyone become admin. Off when the code is empty or under 12 chars; compared in constant time; passed inside a record so the audit aspect never logs it. Staff and hospital users are still created only by an admin.

## Frontend
- **Angular 17 standalone components, no NgModules**: less boilerplate, and lazy loading per route.
- **Signals for component state, RxJS for HTTP/polling**: signals for simple state, RxJS where streams fit (`switchMap` cancels stale polls).
- **Functional interceptors and guards**: the Angular 17 style; JWT is attached in one place and all errors are handled in one place.
- **Guards are UX only**: the server is the real authority.
- **Dashboard polls every 60s**: data changes slowly; websockets would be overkill.
- **nginx serves the SPA and proxies `/api`**: same origin in production, so no CORS needed.

## Build and run
- **Testcontainers MySQL instead of H2**: H2 does not implement MySQL locking or spatial functions the same way.
- **Unit tests via surefire (`*Test`), integration via failsafe (`*IT`)**: `mvn test` stays fast; `mvn verify` runs everything.
- **Multi-stage Dockerfile with layered jar, non-root user**: small image, and code changes don't re-copy dependency layers.
- **ShedLock with DB time**: each job runs on one instance even with several app containers.
- **Spring Boot structured logs (ECS JSON) in the `prod` profile**: logs can be shipped to ELK/Loki as-is; dev keeps readable text with requestId and user in every line.

## Problems found while building (self-annealing log)
- **Testcontainers 1.20 + Docker Engine 29**: Docker 29 raised the minimum API version, so Testcontainers reported "Docker not available". Fixed by overriding `testcontainers.version` to 1.21.4.
- **Two `CorsConfigurationSource` beans** (ours + Spring MVC's): injecting by type failed. Fixed with `cors(Customizer.withDefaults())`, which looks up our bean by name.
- **`EVENT_PUBLICATION` table not found**: Modulith's MySQL SQL uses upper case, and MySQL on Linux has case-sensitive table names. Renamed the table in V1.
- **Audit aspect "JoinPointMatch was NOT bound"**: at `HIGHEST_PRECEDENCE` it ran before Spring's `ExposeInvocationInterceptor`. Moved to `HIGHEST_PRECEDENCE + 100`.
- **Only 3 of 60 units reserved under 50 parallel requests**: `ORDER BY (blood_group = :preferred) DESC` forced a filesort, so InnoDB locked *every* matching row before applying LIMIT, and the other transactions skipped them all. Fixed by querying one blood group at a time, so the index gives `expires_at` order and InnoDB stops after LIMIT rows. The concurrency test caught this; a single-threaded test would not have.
- **Reservation timeout didn't release**: the test DB URL had no `connectionTimeZone=UTC`, so plain JDBC Timestamps were written in IST while Hibernate wrote UTC (5h30 apart). Fixed in the test URL, and the app pins the JVM to UTC at startup.
- **`@let` in an Angular template**: only exists from Angular 18.1; replaced with component methods.
